# Claude Code 마스터 슈퍼프롬프트 — 파킹로그(Parking Log)

> 앱 이름: **파킹로그 (Parking Log)**  
> 제품 형태: **앱인토스 미니앱 · Vite + React + TypeScript · `@apps-in-toss/web-framework` · CSR WebView**  
> 제품 한 줄 정의: **주차한 순간의 위치를 기록하고, 주차 시간과 사용자가 입력한 요금표 기반의 예상 요금까지 확인해 차량을 찾고 정산할 순간을 놓치지 않게 돕는 초간단 주차 기록 서비스.**  
> 브랜드 정체성: 기존 Moment Log에서 주차 기능만 독립시킨 파생 서비스다. 앱인토스 등록용 `appName`은 `parkinglog`를 우선 후보로 제안하되 콘솔 사용 가능 여부와 최종 사용자 승인을 확인한다.
> 슬로건 후보: **"내 차 위치부터 예상 주차요금까지."**
> 작성 기준일: 2026-11-08. 앱인토스 SDK·정책·지원 API와 요금·알림 조건은 구현 시작 시 공식 문서에서 다시 확인한다.

---

## 0. 역할과 최우선 원칙

너는 앱인토스 미니앱을 전문으로 설계·구현하는 시니어 프론트엔드 엔지니어이자 제품 아키텍트다. 기존 Moment Log 프로젝트가 작업 디렉터리에 함께 있더라도 그 프로젝트의 구조를 그대로 복사하지 말고, **주차 기능만 추출해 토스 WebView 환경에 맞는 최소 앱**으로 재설계하라.

우선순위:

1. 토스 미니앱 정책 및 SDK 공식 지원 범위
2. 사용자가 들어와 10초 안에 주차 정보를 저장할 수 있는 단순함
3. 위치·사진 등 개인정보 최소 수집과 로컬 저장
4. 서버·유료 API 없이 핵심 기능 구현
5. iOS·Android 토스 앱에서 동일한 사용 경험
6. 예상 요금은 사용자 입력 요금표 기반으로만 계산하고 실제 청구액처럼 표현하지 않는 정확성
7. 코드·테스트·라이선스·운영 문서의 정확성

### 절대 원칙

- 이 제품은 **독립형 React Native 앱이나 Expo 앱이 아니다. 앱인토스 WebView 미니앱**이다.
- 신규 프로젝트는 구현 시점의 앱인토스 공식 시작 가이드를 확인하고 `npx create-ait-app <app-name>` 등 현재 권장 생성 절차를 우선한다. 기존 저장소가 있다면 먼저 확인하고 덮어쓰지 않는다.
- 서비스 표시 이름은 `파킹로그 (Parking Log)`로 한다. `appName` 후보는 `parkinglog`이며 콘솔 중복 여부·등록 규칙·브랜드 사용 가능 여부를 확인한 뒤 확정한다.
- 앱 아이콘과 워드마크는 Moment Log의 정체성과 연결하되 기존 Moment Log 에셋을 가져올 때 소유권·라이선스를 확인한다. 토스 로고나 타사 주차장 브랜드 로고를 앱 아이콘에 사용하지 않는다.
- 공식 문서가 SDK 3.x를 안내하는 경우 `@apps-in-toss/web-framework` 3.x 및 `apps-in-toss.config.ts` 구성을 우선 검토한다. SDK 2.x의 `granite.config.ts`, `webViewProps`, `outdir` 설정을 무비판적으로 복사하지 않는다.
- SDK 3.x로 출시한 미니앱은 SDK 2.x로 롤백할 수 없다는 공식 주의사항을 고려해 QR/샌드박스와 실제 토스 앱 테스트를 충분히 수행한 뒤 출시한다.
- 렌더링은 CSR/SSG 범위에서 구현한다. SSR, iframe 중첩, `eval`, 외부 웹사이트를 iframe으로 렌더링하는 방식은 사용하지 않는다.
- 토스 SDK의 네이티브 브릿지는 실제 사용자 동작이 필요한 시점에만 호출한다. 화면 렌더링마다 반복 호출하거나 타이머·반복문으로 위치를 조회하지 않는다.
- 첫 진입 시 위치 권한 팝업, 카메라 팝업, 바텀시트를 자동으로 띄우지 않는다. 사용자가 `주차 시작 및 저장` 또는 `주변 사진 촬영`을 누른 시점에 목적을 안내하고 필요한 권한만 요청한다.
- 위치는 기본적으로 **사용자 버튼 입력에 따른 단발성 위치 조회(one-shot)**만 한다. `Device.subscribeLocation`, 백그라운드 위치, 지오펜스, 차량 블루투스 감지는 MVP에 넣지 않는다.
- GPS만으로 지하 주차장 층수·구역·기둥·주차면을 알 수 있다고 주장하지 않는다. 층·구역·기둥 번호는 사용자가 직접 선택·입력한다.
- `latitude/longitude`는 기기가 측정한 좌표일 뿐, 실내 주차면의 정확한 위치가 아니다. 실제 반환된 `accuracy`를 보존하고 정확도가 낮으면 안내를 표시한다.
- 위치 권한을 거부해도 주차장명·층·구역·기둥을 수동 입력해 저장할 수 있어야 한다.
- 사진 저장은 SDK가 반환한 이미지 URI/Base64가 앱 재실행 후에도 유효하고 저장 크기 제한을 통과하는지 POC한 뒤 적용한다. 검증되지 않은 이미지 데이터를 로컬 Storage에 무제한 저장하지 않는다.
- 기본 MVP는 로그인·토스 로그인·회원가입·백엔드·푸시 서버·외부 AI API·유료 지도 SDK·역지오코딩 API 없이 동작해야 한다.
- 주차 타이머는 백그라운드 타이머에 의존하지 않는다. 저장한 `startedAt`과 현재 시각의 차이로 경과 시간을 계산하므로 앱을 닫았다 다시 열어도 시간이 이어진다.
- 예상 요금은 사용자가 주차장 요금표를 직접 입력했을 때만 계산한다. 주차장별 실시간 요금 데이터나 사업자 API가 없는 상태에서 요금을 자동 조회·확정하지 않는다.
- 화면의 금액은 항상 `예상 요금`으로 표시한다. 실제 주차장 정산 시스템의 회차 무료, 할인, 심야/주말 요금, 일 최대요금, 입출차 이벤트, 정산 단위 차이로 실제 금액과 다를 수 있음을 명확히 알린다.
- 실제 주차요금 결제는 MVP에 포함하지 않는다. 특정 주차장 운영사와의 공식 API·가맹점 계약·결제 권한이 확인된 뒤 별도 프로젝트 단계로 검토한다.
- 토스 앱인토스의 `Notification.requestAgreement`는 알림 수신 동의 절차이지 로컬 알림 예약 API가 아니다. 앱인토스의 공개 Client SDK에 로컬 알림 예약 기능이 확인되지 않으면, 앱이 닫힌 상태의 알림을 보장한다고 표현하지 않는다.
- 개인별 주차 종료/정산 알림이 필요하면 앱인토스 기능성 메시지의 공식 서버 연동, anonKey, mTLS, 템플릿 검수, 알림 동의문과 예약 실행 환경을 검증한 선택형 기능으로만 설계한다. 기본 MVP는 서버 없이 타이머와 앱 재진입 시 예상 요금 갱신을 제공한다.
- 기록은 기본적으로 토스 `Storage`에 저장한다. 이 저장소는 사용자 기기 환경에 종속되며 기기 변경 또는 앱 데이터 초기화 시 사라질 수 있음을 명시한다.
- 사용자 위치·사진·주차 정보는 별도 동의 없이 외부 서버로 전송하지 않는다.
- 허위 주소·가짜 GPS·샘플 주차 기록을 실제 사용자 기록으로 표시하지 않는다.
- 외부 지도 앱 열기는 제품 핵심 흐름과 직접 관련된 기능으로 검토하되, 앱인토스의 외부 링크 정책과 테스트 환경에서 허용 여부를 먼저 확인한다. 확인 전에는 출시 기능으로 단정하지 말고 좌표 복사 대안을 제공한다.
- 기존 Moment Log의 보관함·택배·대기번호·구매/반품·OCR·음성 메모·범용 검색 등은 모두 제외한다.
- 라이브러리·TDS 컴포넌트·아이콘·폰트의 버전과 라이선스를 확인한다. 지도 타일·타사 지도 로고·외부 사진 자산은 무단 복제하지 않는다.
- 실제 토스 iOS/Android 앱에서 검증하지 않은 기능을 완료했다고 보고하지 않는다.
- 커밋·푸시·콘솔 업로드·서비스 등록·출시 요청은 사용자 승인 없이 수행하지 않는다.

## 1. 제품 정의 — 주차 순간만 해결한다

### 해결할 문제

대형마트·백화점·아파트·오피스·여행지 주차장에서 차를 세운 뒤, 나중에 주차 위치와 층·구역·기둥 번호를 기억하지 못하는 문제를 해결한다.

### 핵심 가치

- 앱인토스에 진입한다.
- `주차 시작`을 누른다.
- 현재 위치를 가져오거나 수동으로 주차장명을 적는다.
- 층·구역·기둥 번호를 입력하고 저장한다.
- 저장한 시각을 기준으로 주차 타이머가 시작된다.
- 요금표를 알고 있다면 사용자가 직접 입력해 예상 요금을 확인한다.
- 차를 찾을 때 다시 진입하면 주차 경과 시간과 예상 요금을 현재 시각 기준으로 다시 계산한다.
- 실제 정산액은 주차장 정산기/운영사 안내를 기준으로 하며 앱의 예상 요금과 다를 수 있다.

**기본 사용 시나리오:** 주차 기록 생성은 위치 조회와 세부 입력을 포함해 가능한 한 한 화면에서 끝낸다. 요금표 등록은 선택 사항으로 분리해, 주차장명·층·기둥만으로도 빠르게 기록할 수 있게 한다.

### MVP에 남길 기능

1. 주차장 위치 단발성 GPS 기록
2. GPS 권한 거부/실패 시 수동 위치 기록
3. 주차장명 또는 건물명 입력
4. 층 선택: 지하 5층~지하 1층, 지상층, 기타/직접 입력
5. 구역 입력: A/B/C 구역, 문자·숫자 자유 입력
6. 기둥 번호 또는 주차면 번호 입력
7. 주차 시각 자동 기록
8. 선택적 주차 사진 1장(사진 저장 POC 통과 시에만)
9. 현재 주차 정보 표시
10. 지도 앱 열기(토스 외부 이동 정책 확인 통과 시)
11. 위도·경도 복사 대체 기능
12. 주차 경과 시간 타이머: 저장된 주차 시작 시각 기준으로 재진입 후에도 계산
13. 사용자 입력 요금표 기반 예상 주차요금 계산(선택 기능)
14. 주차 종료 시 총 경과 시간·예상 요금 요약 및 실제 결제액 수동 기록(선택)
15. 사용자가 지정한 정산/출차 목표 시각 저장(기본은 앱 내 표시)
16. 주차 완료 처리 및 새 주차 기록
17. 최근 주차 기록 최대 5개(메타데이터만) 보관
18. 기록 삭제 및 전체 초기화

### MVP에서 제외할 기능

- 차량 블루투스 연결 해제 자동 감지
- 상시 GPS 추적, 백그라운드 위치 수집, 지오펜스
- 주차장 층수·기둥·주차면 자동 인식
- 실내 지도, 주차면 내비게이션, 실시간 주차 가능 면 조회
- 주차장 요금 자동 조회, 실제 요금 확정, 실시간 정산 시스템 연동
- 주차장 운영사와 계약하지 않은 상태의 실제 주차요금 결제·자동 출차 결제
- 회차 무료/멤버십 할인/심야/주말/행사 요금 등 복잡한 요금표의 무검증 자동 계산
- 로그인·금융계좌 조회·카드정보 수집·토스머니 조회
- 회원가입, 토스 로그인, 가족 공유, 공유 링크, 소셜 기능
- 기본 MVP의 서버 동기화·클라우드 백업·개인별 원격 푸시 알림(선택형 푸시 POC 통과 전까지 제외)
- OCR, 음성 입력, AI 요약·추천
- 보관함·택배·대기번호 등 다른 Moment Log 템플릿
- 구독·인앱 결제·광고

## 2. 앱인토스 기술 전략

### 2.1 기술 스택

- 앱인토스: 공식 CLI 및 `@apps-in-toss/web-framework`
- SDK: 구현 시점 공식 최신 안정 버전. SDK 3.x 사용 가능 여부와 콘솔 요구사항 확인
- 프론트엔드: React + TypeScript strict
- 개발/번들: Vite + 앱인토스 CLI
- 앱인토스 네이티브 기능: SDK `Device`, `Storage`, `Clipboard` 등 공식 API
- 스타일: 가벼운 CSS 또는 공식 TDS 컴포넌트. TDS 사용 시 현재 React 패키지와 라이선스 확인
- 테스트: Vitest 또는 템플릿에 포함된 안정 테스트 러너, Testing Library
- E2E/기기 검증: 앱인토스 샌드박스·QR 및 실제 토스 앱

### 2.2 앱인토스 생성·설정 원칙

- 신규 프로젝트는 현재 공식 문서의 프로젝트 생성 명령을 우선한다. 예: `npx create-ait-app <app-name>`.
- 생성 후 `package.json`, Vite 설정, `apps-in-toss.config.ts`, SDK 버전을 직접 확인한다.
- SDK 3.x의 대표 설정은 현재 공식 문서 기준 `apps-in-toss.config.ts`, `webView`, `webBundleDir` 형태다. 실제 템플릿과 CLI가 생성한 설정을 우선한다.
- 빌드 스크립트는 공식 예시와 맞춰 Vite 빌드와 `ait build`를 포함하는지 확인한다.
- `appName`은 앱인토스 콘솔에 등록한 실제 앱 식별자와 정확히 일치해야 한다. 임의 이름으로 출시를 가정하지 않는다.
- 미니앱 기본 네비게이션 바를 사용한다. 별도의 자체 상단 닫기/뒤로가기 바를 중복 구현하지 않는다.
- 본 앱은 단일 기능 흐름이므로 자체 탭바를 만들지 않는다. 탭바가 필요하다는 실사용 근거가 생긴 경우에만 공식 플로팅 탭바 기준을 확인한다.
- 앱 진입 즉시 강제 바텀시트나 권한창을 표시하지 않는다.
- 외부 도메인·자사 웹사이트·iframe을 불러오지 않는다.
- 웹 브라우저 미리보기는 UI 확인용이다. 위치·카메라·Storage 브릿지의 실제 동작 검증으로 간주하지 않는다.

### 2.3 반드시 사용할 수 있는 SDK 후보

공식 앱인토스 문서에서 확인되는 후보 API:

- `Device.getLocation({ accuracy })`: 현재 위치를 한 번 가져온다.
- `Device.getLocation.getPermission()` / `Device.getLocation.openPermissionDialog()`: 위치 권한 확인·요청 흐름. 정확한 현재 타입과 호출 방식은 설치된 SDK 타입 정의 확인.
- `Device.openCamera({ base64, maxWidth })`: 카메라를 실행하고 촬영 이미지를 반환한다.
- `Storage.getItem`, `Storage.setItem`, `Storage.removeItem` 등: 모바일 앱 로컬 저장소에 문자열을 읽고 쓴다.
- `Device.openURL(url)`: 기기의 기본 브라우저 또는 관련 앱에서 URL을 연다.
- `Clipboard.setText(text)`: 좌표·장소 정보 복사에 사용 가능 여부와 권한 처리 확인.
- `Device.os`: iOS/Android 분기 시 공식 타입 확인 후 사용.

**주의:** 위 API의 정확한 import 경로, 오류 타입, 인자 타입은 문서 설명만 보고 추측하지 말고 현재 설치된 `@apps-in-toss/web-framework`의 타입 정의와 공식 SDK 문서에서 다시 확인한다. SDK API를 직접 `window` 객체에서 임의 호출하는 코드를 만들지 않는다.

### 2.4 저장소 선택

- 운영 환경에서는 앱인토스 `Storage` API를 기본 사용한다.
- 저장 데이터는 작은 JSON 문자열로 제한한다.
- 데이터는 기기 로컬에 저장되며 기기 변경·앱 데이터 초기화 시 사라질 수 있다. 화면 또는 설정의 데이터 안내에 명시한다.
- MVP에는 Supabase·Firebase·Cloudflare·자체 API 서버를 추가하지 않는다.
- `window.localStorage`는 로컬 브라우저 미리보기/테스트 전용 Adapter로만 허용한다. 토스 운영 환경의 기본 저장소로 사용하지 않는다.
- `Storage` API의 키별/전체 용량·문자열 크기 제한이 공식 문서에 명시되지 않았다면 실제 기기 POC로 확인하고, 미확인 제한을 추정하지 않는다.

## 3. 핵심 화면과 사용자 흐름

화면은 세 가지 상태만 갖는 단일 흐름으로 시작한다.

### 3.1 첫 진입 — 저장된 주차 기록 없음

표시:

- 제목: `내 차 어디에 세웠지?`
- 설명: `주차 위치와 시간을 한 번에 기록해 두세요.`
- 주요 CTA: `주차 시작 및 저장`
- 보조 안내: `위치 권한 없이도 주차장명과 위치 정보를 직접 입력할 수 있어요.`

초기 화면에서 위치 권한, 카메라 권한, 로그인, 알림 동의를 자동으로 요청하지 않는다. 예상 요금은 요금표를 등록하지 않은 사용자의 첫 화면에 강제로 노출하지 않는다.

### 3.2 주차 기록 화면

한 화면 안에서 저장까지 끝내는 것을 목표로 한다.

**A. 위치 영역**

- 버튼: `현재 위치 가져오기`
- 위치 조회 중에는 버튼 중복 실행 방지 및 로딩 표시
- 성공하면 위도·경도 대신 가능한 경우 `위치가 기록되었어요`와 실제 정확도(예: `측정 오차 약 18m`)를 우선 표시
- 좌표 상세값은 접을 수 있는 보조 정보로 제공
- GPS 정확도가 낮거나 위치를 가져오지 못하면 `실내 주차장에서는 GPS가 부정확할 수 있어요. 주차장명과 층을 직접 입력해 주세요.` 표시
- 위치 권한 거부 시 재요청 버튼과 수동 입력 대안 제공
- 위치 조회가 실패해도 기록 화면을 닫거나 앱 사용을 막지 않는다.

**B. 주차 정보**

필수값은 최소화한다. 주차장명, 층, 구역, 기둥/주차면 번호는 선택 입력이며 좌표가 없더라도 장소명·층·번호로 저장 가능해야 한다. 주차 시작 시각은 현재 시각으로 자동 기록하고, 사용자가 실제 주차 시각을 알고 있으면 수정할 수 있다.

- 주차장/건물명: 텍스트 입력, placeholder `예: 스타필드 하남`
- 층: 칩 선택 `B5 B4 B3 B2 B1 1F 2F 3F 기타`
- 기타 선택 시 짧은 텍스트 입력
- 구역: 텍스트 입력, placeholder `예: A구역 / 노란 기둥`
- 기둥/주차면 번호: 텍스트 입력, placeholder `예: A-12 / 305번`
- 메모: 선택 입력, 최대 길이 제한
- 주차 시각: 현재 기기 시각 자동 입력. 필요 시 수정은 후순위

**C. 사진**

- 사진 기능은 옵션이다. 기본 기록을 위해 사진 권한이 필요하지 않다.
- `주변 사진 촬영` 버튼을 눌렀을 때만 `Device.openCamera`를 호출한다.
- 사진은 기둥·층 표지판·주변 위치 식별용으로 최대 1장만 사용한다.
- 사진 저장의 지속성·크기 제한 POC가 통과한 경우에만 저장한다. POC 실패 시 사진 기능은 MVP에서 숨기고 텍스트 입력을 유지한다.
- 사진을 외부 서버로 업로드하지 않는다.

**D. 선택 요금 정보**

- 접을 수 있는 `예상 요금 계산` 영역을 제공한다. 기본값은 꺼짐이다.
- 사용자가 주차장 요금표를 확인한 경우에만 무료 시간, 기본 요금, 기본 적용 시간, 추가 과금 단위(분), 추가 요금을 입력한다.
- 선택적으로 1회 주차 최대 요금을 입력할 수 있으나, 일 단위/자정 초기화 요금표는 MVP 계산 대상에서 제외한다.
- 입력 요금표는 사용자 로컬 프로필로 저장해 같은 주차장을 다시 이용할 때 불러올 수 있다.
- 요금 정보가 없으면 타이머만 표시하고 금액을 추측하지 않는다.

**E. 저장**

- 하단 고정 CTA: `주차 시작 및 저장`
- 저장 전에 GPS 정확도와 입력한 층·구역·기둥, 주차 시작 시각을 요약한다. 요금표가 설정된 경우 `예상 요금 계산이 적용돼요`라고 표시한다.
- 저장 성공 즉시 타이머가 보이는 주차 진행 화면으로 전환한다.
- 저장 실패 시 입력값을 유지하고 재시도할 수 있게 한다.

### 3.3 주차 진행 화면

활성 주차 기록이 있을 때 기본 진입 화면으로 보여 준다.

- 상단 제목: `내 차 위치`
- 저장 시각: `오늘 14:32 주차 시작`
- 가장 중요한 정보: `주차한 지 1시간 24분`처럼 경과 시간을 크게 표시한다. 이 값은 고정 카운터가 아니라 `now - startedAt`으로 매번 계산한다.
- 주차장명, 층, 구역, 기둥/면 번호를 타이머 바로 아래에 표시한다.
- 위치 상태: `GPS 기록됨` / `수동 입력` / `위치 권한 없음` 구분
- 실제 GPS 오차가 있으면 표시한다.
- 요금표가 저장된 경우에만 `예상 주차요금 약 3,000원`을 표시한다.
- 금액 바로 아래에 `사용자가 입력한 요금표 기준 · 실제 정산 금액과 다를 수 있어요`를 표시한다.
- 요금표가 없으면 요금 영역을 보여 주지 않거나 `요금표 등록 시 예상 요금을 볼 수 있어요`라는 선택 안내만 표시한다.
- 주요 버튼: `지도에서 위치 보기`(외부 이동 정책 확인 통과 시)
- 대체 버튼: `좌표 복사`
- 보조 버튼: `주차 정보 수정`, 요금표가 있으면 `요금표 수정`
- 앱 밖 알림 기능성 푸시가 승인·구현된 경우에만 `정산/출차 알림 설정`을 노출한다. 그렇지 않으면 알림 설정 UI를 노출하지 않는다.
- 종료 버튼: `차량 찾았어요`

타이머는 앱이 열린 동안에만 1분 단위로 화면을 갱신한다. 앱을 닫았을 때 백그라운드 작업이나 타이머를 유지하지 않는다. 다시 진입하면 현재 시각과 저장된 시작 시각으로 경과 시간을 재계산한다.

실내 주차장 GPS는 부정확할 수 있으므로 지도 핀은 주변 또는 건물 입구를 가리킬 수 있다. 지도 안내를 통해 지하 주차면까지 정확히 찾을 수 있다고 표현하지 않는다.

### 3.4 주차 종료 및 정산 요약

사용자가 `차량 찾았어요`를 누르면 종료 확인을 거친다.

- 종료 시각 `endedAt`과 총 주차 경과 시간을 저장한다.
- 요금표가 있는 경우 종료 시각 기준 예상 요금을 계산해 보여 준다.
- 실제 정산 금액은 선택 입력으로 기록할 수 있다. 이 값은 사용자가 주차장 정산기에서 확인한 금액이며 앱의 예상 값과 구분한다.
- `예상 요금`과 `실제 정산 금액` 차이를 보여 줄 수 있지만, 앱 계산이 실제 요금과 다를 수 있는 이유(할인·일 최대요금·운영사 요금 규칙 미지원)를 함께 안내한다.
- `주차 완료` 처리 후 활성 기록을 최근 기록으로 이동하고 새 주차 시작 버튼을 제공한다.
- 완료한 기록을 수정할 때 종료 시각과 요금표 스냅샷은 명시적 수정 없이는 바꾸지 않는다.

### 3.5 요금표 관리

- 요금표는 선택 기능이다. 등록하지 않아도 주차 위치 기록과 타이머를 사용할 수 있다.
- 최근 사용한 요금표를 로컬에 최대 5개 저장한다.
- 요금표 이름은 주차장명 또는 사용자가 입력한 별칭으로 저장한다.
- MVP 입력 항목: 무료 시간(분), 기본 요금(원), 기본 적용 시간(분), 추가 과금 단위(분), 추가 단위 요금(원), 1회 주차 최대 요금(선택).
- 각 입력값에는 단위와 짧은 예시를 제공한다. 예: `무료 10분`, `기본 60분 2,000원`, `이후 10분마다 500원`.
- 요금표가 바뀌어도 과거 주차 기록에는 당시 사용한 `rateSnapshot`을 보존한다.
- `일 최대요금`, 자정 초기화, 주말/심야 할증, 할인·인증·회차 조건이 있는 주차장은 MVP 자동 계산 대상에서 제외한다. 해당 주차장에서는 타이머만 사용하거나 사용자가 직접 요금표가 단순화될 수 있음을 이해하고 근사 규칙을 입력하도록 한다.

### 3.6 새 주차 기록과 기존 기록 처리

현재 활성 주차 기록이 존재하는 상태에서 새 기록을 저장하면 기존 기록을 덮어쓰지 않고 최근 기록 목록으로 이동한다.

- 활성 기록: 1개
- 최근 기록: 최대 5개, 사진 데이터 제외
- 새 기록 저장 시 기존 활성 기록은 History 앞에 추가한다. 완료되지 않은 기존 기록을 새 기록으로 덮지 말고, 새 기록 생성 전 사용자에게 기존 주차를 종료할지 확인한다.
- 5개를 넘으면 가장 오래된 기록부터 제거한다.
- 사용자가 `차량 찾았어요`를 누르면 종료 시각을 저장한 뒤 기록을 최근 목록으로 이동한다.
- 삭제는 확인 UI를 거친다.

### 3.7 최근 기록

초기 MVP에서는 주차 진행 화면 아래에 접을 수 있는 `최근 주차 기록` 영역으로 제공한다.

각 행은 저장 날짜/시간, 주차장명, 층, 구역 요약만 보여 준다. 탭하면 상세 위치를 확인할 수 있다.

최근 기록은 복잡한 검색·타임라인으로 확장하지 않는다.

## 4. 위치 수집·정확도·지도 이동 정책

### 4.1 위치 획득

- 사용자가 `현재 위치 가져오기`를 눌렀을 때만 `Device.getLocation`을 호출한다.
- 주차 기록에 적합한 정확도 옵션(공식 `Accuracy.High` 등)을 검토하되, 현재 SDK 타입 정의에 실제 존재하는 값을 확인한다.
- 위치를 가져온 시각(timestamp), 위도, 경도, accuracy를 모두 보존한다.
- Android에서 `FINE` 또는 `COARSE` 접근 범위 정보가 반환되면 이를 구분해 안내한다.
- 중복 클릭으로 네이티브 위치 API가 여러 번 호출되지 않도록 진행 중 상태를 관리한다.
- 짧은 시간 내 재시도는 사용자 버튼 동작으로만 허용한다. 무한 재시도·폴링 금지.
- 위치 권한이 거부되면 수동 저장을 유지하고, 앱 진입 시 반복해서 권한을 강제하지 않는다.

### 4.2 GPS 오차 처리

- `accuracy`는 실제 SDK에서 반환된 측정 오차값으로 기록한다.
- 화면에서 임의로 0m 또는 특정 정확도를 표시하지 않는다.
- 정확도가 좋지 않으면 경고 문구만 표시하고, 사용자가 수동 세부 위치를 입력할 수 있게 한다.
- 위도·경도·고도만으로 지하층, 실내 위치, 기둥 번호, 차량 위치를 추론하지 않는다.
- 위치가 없는 기록은 지도 버튼을 비활성화하고 수동 장소·층·구역 정보를 보여 준다.

### 4.3 주소/역지오코딩

- MVP에는 주소 자동 변환 API를 넣지 않는다.
- 유료 지도·역지오코딩 API를 기본 도입하지 않는다.
- 주차장/건물명은 사용자가 직접 입력한다.
- 공식 OS/SDK가 별도 무료 주소 변환 기능을 제공하는지 구현 시점에 확인하되, 확인되지 않으면 수동 입력을 사용한다.

### 4.4 지도 앱 열기

- 지도 열기는 저장된 위도·경도에 대한 외부 지도 링크를 구성하는 방식부터 검토한다.
- 앱인토스 `Device.openURL`을 사용하고, iOS/Android OS에 맞는 공식 지도 URL 형식 및 실제 토스 앱 동작을 검증한다.
- 이 기능은 주차 위치를 다시 찾기 위한 앱의 핵심 흐름과 직접 관련되지만, 앱인토스 외부 링크 정책에서 허용되는지 구현 전에 공식 가이드와 콘솔/채널톡으로 확인한다.
- 허용 여부가 확인되지 않은 상태에서는 출시 기능으로 활성화하지 않는다.
- 외부 이동이 허용되지 않거나 설치 지도 앱이 열리지 않는 경우 `좌표 복사`를 제공하고, 좌표를 화면에 직접 표시한다.
- 외부 지도에서 주차장 내부 층·구역·주차면까지 안내하는 것처럼 표현하지 않는다.
- 지도 타일·장소 이미지·지도 서비스 로고를 앱 화면에 무단 삽입하지 않는다.

## 5. 선택 사진의 저장 정책 — 반드시 POC 후 결정

토스 SDK의 `Device.openCamera`는 카메라 촬영 이미지를 반환한다. 그러나 카메라 결과를 다음 접속에서도 안정적으로 표시할 수 있는지, 앱인토스 `Storage`에 어느 정도 크기의 문자열을 저장할 수 있는지는 현재 SDK 문서만으로 단정하지 않는다.

### Phase 0 사진 POC

1. iOS 토스 앱에서 카메라를 실행하고 이미지 1장을 반환받는다.
2. Android 토스 앱에서 동일 동작을 확인한다.
3. `maxWidth`를 1024 이하로 제한한다.
4. 필요한 경우 WebView Canvas 등 지원되는 표준 이미지 처리 방식으로 JPEG를 축소·압축한다. `createImageBitmap`, Canvas, Blob 등은 대상 WebView에서 동작하는지 확인한다.
5. 최대 1장만 저장하는 설계를 검증한다.
6. SDK `Storage.setItem`으로 저장한 뒤 미니앱을 완전히 닫고 다시 진입해 사진이 다시 표시되는지 확인한다.
7. 실제 저장 가능한 최대 크기·실패 동작·앱 재실행 지속성을 기록한다.
8. 이미지 크기가 저장 한도를 넘거나 재실행 후 URI가 무효라면 사진 저장을 MVP에서 제외한다.

### 사진 저장에 성공한 경우

- 활성 주차 기록에만 사진 1장을 연결한다.
- 최근 기록에는 사진을 보관하지 않는다.
- 압축 후 파일 크기 상한은 실측한 Storage 한도보다 충분히 낮게 정한다.
- 사용자가 사진 삭제를 누르면 이미지 키를 즉시 제거한다.
- 새 주차 저장 시 이전 활성 사진도 함께 History에 옮기지 않고 제거해 저장 공간을 제한한다.
- 사진을 외부 서버·클라우드에 업로드하지 않는다.

### 사진 저장에 실패한 경우

- 카메라 버튼을 MVP에서 숨기거나 `사진 저장은 현재 지원하지 않아요`라고 안내한다.
- 임시 미리보기만 제공한 채 영구 보관되는 것처럼 표현하지 않는다.
- 주차장명·층·구역·기둥 번호·메모로 핵심 가치가 유지되도록 한다.

## 6. 데이터 모델 — 위치·타이머·요금표 스냅샷

별도 관계형 데이터베이스를 만들지 않는다. 앱인토스 `Storage`에 저장하는 버전 관리 JSON 구조로 충분한지 먼저 검증한다. 요금표가 바뀌어도 과거 기록의 예상 요금 기준이 바뀌지 않도록 각 기록에 요금표 스냅샷을 보존한다.

```ts
export type LocationSource = 'TOSS_GPS' | 'MANUAL' | 'NONE';
export type ParkingStatus = 'ACTIVE' | 'COMPLETED';
export type ReminderMode = 'IN_APP_ONLY' | 'FUNCTIONAL_PUSH';

export interface ParkingLocation {
  latitude: number;
  longitude: number;
  accuracyMeters: number | null;
  capturedAt: string;
  accessLocation?: 'FINE' | 'COARSE';
}

/** MVP에서 지원하는 단순 요금표 형식만 표현한다. */
export interface ParkingRateRule {
  freeMinutes: number;             // 입차 후 무료 시간(1회)
  baseMinutes: number;             // 무료 시간 이후 기본 요금에 포함되는 분
  baseFeeWon: number;              // 기본 요금(원)
  additionalUnitMinutes: number;   // 추가 과금 단위(분)
  additionalUnitFeeWon: number;    // 추가 단위당 요금(원)
  maxFeePerSessionWon: number | null; // 1회 주차 최대 요금. 일 최대요금과 혼동 금지
  ruleType: 'BASE_PLUS_INCREMENT';
  userConfirmedAt: string;
}

export interface ParkingRateProfile {
  id: string;
  name: string;                    // 예: 스타필드 하남
  parkingLotName: string;
  rule: ParkingRateRule;
  createdAt: string;
  updatedAt: string;
}

export interface ParkingRecord {
  id: string;
  schemaVersion: 2;
  savedAt: string;
  startedAt: string;               // ISO 8601 timestamp; 경과 시간 계산의 기준
  endedAt: string | null;
  timezone: string;                // IANA timezone (예: Asia/Seoul)
  status: ParkingStatus;
  parkingLotName: string;
  floor: string;
  zone: string;
  pillarOrSpot: string;
  note: string;
  locationSource: LocationSource;
  location: ParkingLocation | null;
  rateProfileId: string | null;
  rateSnapshot: ParkingRateRule | null;
  actualPaidFeeWon: number | null; // 사용자가 정산기에서 확인해 직접 입력한 금액
  reminderAt: string | null;
  reminderMode: ReminderMode;
  hasPhoto: boolean;
}

export interface ParkingStateV2 {
  schemaVersion: 2;
  activeRecord: ParkingRecord | null;
  recentRecords: ParkingRecord[];   // 최신 5개
  rateProfiles: ParkingRateProfile[]; // 최신 5개
}

export interface ParkingFeeEstimate {
  amountWon: number;
  elapsedMinutes: number;
  billableMinutes: number;
  isCapped: boolean;
  basis: 'USER_ENTERED_RATE';
  warning: 'ESTIMATE_ONLY';
}
```

### 6.1 타이머 계산 정책

- `startedAt`은 UTC ISO 8601 시각으로 저장하고 `timezone`은 표시용 현지 타임존으로 저장한다.
- 경과 시간은 `now - startedAt`으로 계산한다. `setInterval` 카운터를 데이터의 원천으로 삼지 않는다.
- 앱이 백그라운드/종료된 동안에도 타이머는 별도 실행하지 않는다. 다시 열면 현재 시각을 기준으로 계산 결과가 따라잡힌다.
- 기기 시계가 크게 변경되거나 `now < startedAt`이면 음수 시간을 표시하지 말고 데이터 이상 안내와 수정/재설정 경로를 제공한다.
- 화면이 열린 동안에만 1초 또는 1분 단위로 표시를 갱신한다. 초 단위 정확성이 필요하지 않으면 1분 갱신을 우선한다.
- 차량을 찾았다고 완료 처리한 시점의 `endedAt`을 저장하고 타이머를 고정한다.

### 6.2 예상 요금 계산 정책

MVP는 다음의 단순 요금표만 지원한다.

1. 무료 시간 `freeMinutes`를 1회 적용한다.
2. 무료 시간이 끝난 뒤 `baseMinutes` 이내에는 `baseFeeWon`을 적용한다.
3. 기본 시간 초과분은 `additionalUnitMinutes` 단위로 올림 계산하고, 단위마다 `additionalUnitFeeWon`을 더한다.
4. `maxFeePerSessionWon`이 설정되어 있으면 1회 주차 최대 요금을 상한으로 적용한다.
5. 모든 금액은 사용자가 주차장 현장 안내판/운영사 정보에서 직접 확인해 입력한다.

기본 계산 규칙:

```ts
const billable = Math.max(0, elapsedMinutes - rule.freeMinutes);
let estimate = 0;
if (billable > 0) {
  estimate = rule.baseFeeWon;
  if (billable > rule.baseMinutes) {
    const extraMinutes = billable - rule.baseMinutes;
    const units = Math.ceil(extraMinutes / rule.additionalUnitMinutes);
    estimate += units * rule.additionalUnitFeeWon;
  }
}
if (rule.maxFeePerSessionWon != null) {
  estimate = Math.min(estimate, rule.maxFeePerSessionWon);
}
```

위 계산식은 순수 함수로 구현하고 단위 테스트를 작성한다. `baseMinutes`가 0일 때, 무료 시간 경계, 기본 시간 경계, 추가 단위 직전/직후, 최대 요금 경계, 0원 요금표, 잘못된 음수/0 단위 입력을 테스트한다.

예시 테스트 픽스처: 무료 10분, 기본 60분 2,000원, 이후 10분마다 500원인 요금표에서 총 주차 70분이면 과금 대상 60분이므로 2,000원, 총 주차 75분이면 과금 대상 65분이므로 추가 1단위가 적용되어 2,500원으로 계산한다. 이는 알고리즘 예시일 뿐 실제 특정 주차장의 요금표를 의미하지 않는다.

**지원하지 않는 요금 규칙:** 일 최대요금(자정/24시간 리셋), 시간대별·요일별 요금, 심야/주말/공휴일 할증, 회차 무료 조건, 차량 종류별 요금, 멤버십·영수증·쇼핑 할인, 전기차 할인, 사전정산 할인, 출차 지연 재과금, 입출차 이벤트 기반 요금은 MVP에서 자동 계산하지 않는다. 이런 조건이 있는 주차장은 `예상 요금 계산을 사용하지 않음` 또는 사용자가 직접 확인한 단순 근사 요금만 입력하도록 안내한다.

- 요금표가 없으면 금액을 절대 추정하지 않는다.
- 화면에는 `예상 요금`과 `사용자 입력 요금표 기준`을 함께 표시한다.
- `실제 요금`, `결제 예정 금액`, `자동 정산` 등의 표현은 사용하지 않는다.
- 실제 정산 금액은 사용자가 출차 정산기에서 확인한 뒤 직접 입력하는 별도 필드다.
- 과거 기록의 예상 금액을 다시 계산할 때는 기록의 `rateSnapshot`과 `endedAt` 또는 조회 시각을 사용한다.

### 6.3 저장 키 제안

- `parking.state.v2`: 활성 주차 기록, 최근 기록, 로컬 요금표 JSON
- `parking.photo.active.v1`: 사진 POC 통과 시에만 활성 기록 사진 데이터
- `parking.reminder.preference.v1`: 알림 기능 활성화 여부/사용자 동의 상태를 저장해야 할 경우. 토스 SDK 공식 응답과 저장 정책 확인 후 결정

### 6.4 마이그레이션·검증

- 기존 `parking.state.v1`이 존재하면 v1 기록에 `startedAt = savedAt`, `endedAt = null`, `rateSnapshot = null`, `actualPaidFeeWon = null`을 채워 v2로 마이그레이션한다.
- `rateSnapshot`이 없는 이전 기록은 타이머만 표시하고 요금을 소급 계산하지 않는다.
- JSON parse 실패 시 앱 전체가 중단되지 않아야 한다. 손상 데이터 안내와 안전한 초기화/복구 경로를 제공한다.
- 저장 전 길이·형식·위도/경도 범위·금액 범위·분 단위 범위를 검증한다.
- 로그에 좌표·주차장명·기둥 번호·사진 데이터 URI·실제 결제액을 기록하지 않는다.

## 8. 주요 모듈의 책임

### `parking.types.ts`

- `ParkingRecord`, `ParkingLocation`, `ParkingStateV2` 정의
- 상태와 데이터 버전 정의
- SDK 타입을 도메인에 직접 노출하지 않는다.

### `parking.validation.ts`

- 층 선택값 검증
- 구역·기둥·메모 길이 제한
- 위도 `-90~90`, 경도 `-180~180` 검증
- accuracy가 음수거나 유효하지 않으면 `null` 처리
- 빈 입력도 최소한의 유효 기록으로 저장 가능한지 정책 정의

### `parking.service.ts`

순수 제품 로직:

- 신규 주차 기록 생성
- 현재 기록 수정
- 주차 완료
- 새 기록 시작 시 기존 활성 기록을 History로 이동
- 최근 기록 최대 5개 유지
- 사진 삭제 시 활성 사진 참조 제거

### `parking.repository.ts`

- `StorageAdapter` 인터페이스를 통해 상태를 읽고 쓴다.
- 기록 상태 JSON의 parse/serialize 및 버전 확인
- 저장 실패·파싱 실패 처리
- 실제 SDK API 호출은 하지 않는다.

### `parking-timer.ts`

- 저장된 `startedAt`과 `now`를 받아 경과 시간(분/시/일)을 반환하는 순수 함수
- 타이머를 초 단위로 누적하지 않는다. 앱 종료/백그라운드 구간은 현재 시각과 시작 시각 차이로 계산한다.
- 표시 형식은 `1시간 24분`, `1일 2시간`처럼 간단하게 한다.
- 주차 종료 시 `endedAt`을 고정하고 최종 경과 시간을 산출한다.

### `fee-estimator.ts`

- `ParkingRateRule`과 `elapsedMinutes`를 받아 예상 요금을 계산하는 순수 함수
- 사용자 입력값의 유효성을 검사한다. 0 또는 음수의 과금 단위, 음수 요금, 비정상적으로 큰 값은 거부한다.
- `Math.ceil` 방식의 추가 과금 단위를 적용하고 경계값 테스트를 수행한다.
- 요금 계산 결과는 `USER_ENTERED_RATE` 및 `ESTIMATE_ONLY` 표식을 포함한다.
- 요금표가 없거나 지원하지 않는 복합 요금표이면 숫자를 생성하지 않고 `NOT_CONFIGURED` 또는 `UNSUPPORTED_RATE_RULE` 상태를 반환한다.
- 실제 결제 API·주차장 데이터 API를 호출하지 않는다.

### `reminder-policy.ts` / `toss-notification.adapter.ts` (선택 기능)

- `Notification.requestAgreement`는 알림 동의 절차에만 사용한다. 로컬 알림 예약 API처럼 취급하지 않는다.
- 앱인토스의 공식 기능성 메시지 API는 파트너 서버에서 mTLS로 호출하는 구조다. 사용자 식별에는 토스 로그인 `userKey` 또는 로그인 없는 익명 식별키 `anonKey` 중 하나를 쓸 수 있다.
- 로그인 없는 구성을 유지하려면 anonKey 발급·검증·보관·철회 흐름을 검토한다. anonKey도 사용자 식별자이므로 개인정보·보안 문서에 데이터 흐름을 기록한다.
- 사용자가 지정한 주차 종료/정산 알림은 사용자 동의문, 승인된 기능성 메시지 템플릿, 서버 예약 작업, 메시지 발송 API가 모두 준비된 경우에만 제공한다. 콘솔에서 제공하는 전체 사용자 대상 일회성/정기 발송은 개인별 주차 세션의 `reminderAt`에 맞춘 알림을 대체하지 못한다.
- 위치 좌표·층·구역·기둥 번호·사진·요금표는 알림 서버에 전송하지 않는다. 알림 발송에 필요한 익명 식별자와 dueAt, 최소 상태만 저장하는 설계를 우선한다.
- 서버 비용·Cron 실행 한도·mTLS 인증서 지원·비밀키 관리가 검증되지 않으면 푸시 기능을 보류한다. 타이머는 서버 없이 계속 작동한다.
- 알림 본문은 개인정보를 최소화해 `주차 정산을 확인할 시간이에요.`처럼 작성한다. 주차장명·좌표·층·기둥 번호·예상 요금은 푸시에 넣지 않는다.
- 메시지 발송 성공 응답과 사용자의 실제 단말 수신은 구분해 테스트하고, 발송 성공만으로 전달 완료라고 표시하지 않는다.

### `toss-location.adapter.ts`

- `Device.getLocation` 단발 호출
- 권한 오류와 기타 오류를 구분
- 실제 accuracy, timestamp, 위경도만 도메인 타입으로 변환
- 위치 구독/백그라운드 수집 API를 제공하지 않는다.

### `toss-storage.adapter.ts`

- 앱인토스 `Storage` API만 호출
- JSON 문자열 key-value 읽기/쓰기/삭제
- SDK 오류를 도메인 오류로 매핑
- 호출 수를 최소화하고 저장 실패 시 UI가 복구 가능하게 한다.

### `toss-camera.adapter.ts`

- POC 통과 시에만 추가
- 사용자가 버튼을 누른 경우에만 카메라 실행
- 이미지 최대 크기와 최종 저장 크기 제한
- 사진 1장만 관리
- 외부 업로드 없음

### `toss-map-navigation.adapter.ts`

- 좌표를 지도 URL로 변환하는 순수 함수
- iOS/Android URL 형식을 분리
- 실제 열기는 `Device.openURL` Adapter에서 수행
- 외부 링크 정책 미확인 시 기능 플래그 off

### `toss-clipboard.adapter.ts`

- 위도·경도 또는 직접 입력한 주차장 정보를 텍스트로 복사
- SDK의 클립보드 API 지원 여부 및 권한 처리 검증
- 복사 실패 시 화면에서 좌표를 선택·복사할 수 있는 대안 제공

## 9. UI/UX 디자인 시스템

디자인 방향: **한 가지 행동에 집중하는 가벼운 생활 유틸리티**.

- 토스 앱인토스의 기본 내비게이션 바와 Safe Area를 존중한다.
- 별도 탭바, 복잡한 대시보드, 온보딩 캐러셀, 로그인 화면을 만들지 않는다.
- 홈 화면에서 주차 상태와 다음 행동을 즉시 이해할 수 있어야 한다.
- 기본 CTA는 화면 내 가장 명확한 버튼 한 개로 제한한다.
- 입력 필드는 필요한 경우에만 보여 준다.
- GPS 위치를 가져오는 동안 진행 상태와 실패 원인을 표시한다.
- 층 선택은 큰 칩/버튼으로 처리해 차량에서 내린 직후 빠르게 조작할 수 있게 한다.
- 터치 영역, 대비, 한글 줄바꿈, 큰 글자, 스크린 리더 레이블을 확인한다.
- 이미지나 장식보다 주차장명·층·기둥 번호를 우선 표시한다.
- 위치 정확도는 색상만으로 표현하지 않는다. `정확도 양호`, `오차가 클 수 있음`처럼 텍스트를 함께 표시한다.
- 활성 주차 중에는 경과 시간을 핵심 정보로 크게 보여 준다. 시간은 `startedAt` 기반으로 재계산한다.
- 요금표가 등록된 경우에만 예상 금액을 보여 주고, 금액 옆에 `실제 정산 금액과 다를 수 있어요`를 표시한다.
- 요금 미설정 상태에서 0원 또는 임의 추정액을 표시하지 않는다.
- 주차 완료/기록 삭제/새 기록 덮어쓰기 전에는 확인을 받는다.
- 앱이 처음 열렸을 때 자동 권한 팝업이나 팝업형 바텀시트를 표시하지 않는다.
- OS Back/토스 네비게이션을 방해하지 않는다.

## 10. 개인정보·권한·운영 정책

### 위치

- 위치는 주차 저장을 누른 사용자의 명시적 행동이 있을 때만 한 번 가져온다.
- 위치 권한 요청 전에 `주차장 주변 위치를 저장하는 데 사용해요`라고 안내한다.
- 위치 데이터는 토스 Storage에 저장하며 외부 서버로 전송하지 않는다.
- 위치를 가져오지 못해도 앱 기능을 계속 사용할 수 있다.
- 백그라운드 위치 권한은 요청하지 않는다.

### 사진

- 사진은 사용자가 직접 카메라 버튼을 눌렀을 때만 촬영한다.
- 사진 저장 POC가 통과한 경우에만 앱인토스 로컬 Storage에 저장한다.
- 사진을 분석·업로드·공유하지 않는다.
- 사진을 저장할 수 없는 경우 그 사실을 숨기지 않는다.

### 데이터 삭제

- `현재 주차 기록 삭제`는 해당 기록과 연결 사진만 삭제한다.
- `최근 기록 전체 삭제`는 최근 기록 키만 삭제한다.
- `모든 주차 정보 삭제`는 앱이 소유한 키만 삭제한다.
- 토스 Storage의 다른 미니앱 데이터나 다른 앱 영역을 삭제하지 않는다.

### 로그인·서버

- 기본 MVP는 로그인 및 계정 생성이 없다.
- 기본 주차 기록, 타이머, 예상 요금 계산은 토스 Storage만 사용하고 백엔드·DB·클라우드 스토리지를 사용하지 않는다.
- 기본 MVP는 토스 사용자 식별키를 수집하지 않는다.
- 개인별 앱 종료 후 푸시 알림을 구현할 때만 선택적으로 anonKey를 검토한다. 이 경우에도 Toss Login의 실명·이메일 정보는 수집하지 않는다.
- 푸시 기능용 서버에는 GPS 좌표, 주차 사진, 층·구역·기둥 번호, 요금표를 저장하지 않는다. 알림 발송에 필요한 최소 익명키와 발송 시각만 처리한다.
- 데이터 기기 간 동기화는 지원하지 않는다. 동기화는 사용자가 명시적으로 새 요구를 제시하고 비용·보안 검토가 끝난 뒤에만 고려한다.

### 토스 정책 준수

- 외부 앱 설치를 유도하지 않는다.
- 자사 웹사이트나 임의의 외부 웹페이지로 보내지 않는다.
- 지도 앱 이동은 주차 위치 확인이라는 핵심 기능에 필요한 링크인지 공식 정책을 확인하고, 미승인 시 좌표 복사만 제공한다.
- 앱의 주요 흐름은 미니앱 안에서 끝나야 한다.
- 토스의 기본 상단 내비게이션을 사용한다.
- SDK 브릿지 과도 호출 금지.
- 앱 진입 즉시 바텀시트/권한 팝업 금지.
- 민감한 위치정보 수집은 명시적인 이용자 동의와 최소 수집 원칙을 따른다.

## 11. 무료·저작권·라이선스 원칙

### 무료 구현

- 별도 서버 없이 토스 SDK와 로컬 Storage만으로 위치 기록·타이머·요금 추정을 구현한다.
- 유료 지도 SDK·지도 타일 API·역지오코딩·AI API·푸시 서버·외부 파일 저장 서비스를 기본 사용하지 않는다.
- 사용자 입력 요금표 기반 계산은 추가 API 비용이 없는 순수 로컬 로직으로 구현한다.
- 앱인토스의 기능성 푸시는 광고성 스마트 발송과 구분한다. 2026-08-28 공지에 따라 광고성 푸시/알림 운영은 2026-10-01 종료됐고 기능성 메시지만 유지된다고 문서화한다.
- 개인별 정산/출차 시각 푸시는 서버 mTLS 연동, anonKey, 사용자 알림 동의, 승인 템플릿, 예약 실행 환경이 모두 필요하다. 무료 실행 환경의 mTLS·스케줄링 지원이 검증되지 않으면 MVP에 포함하지 않는다.
- 서버/푸시를 선택적으로 도입할 경우 무료 한도, 실행 횟수, 비활성 중지 정책, 데이터 보존 및 인증서 보안 비용을 별도 검증한다.
- 지도 앱 열기는 공식 지도 URL과 앱인토스 `Device.openURL` 조합을 검토하되, 플랫폼 외부 링크 정책 승인 전에는 비활성화한다.
- 사진이 로컬 Storage에 안정적으로 저장되지 않으면 사진 기능을 제외한다. 무료 호스팅을 급히 붙여 문제를 덮지 않는다.
- 앱인토스 파트너 등록·계약·콘솔 이용·운영 조건은 별도로 확인한다. 코드 구현이 무료라는 이유로 파트너 등록과 모든 운영 과정이 무조건 무료라고 주장하지 않는다.

### 결제·금융 연동 범위

- MVP에서 실제 주차요금을 수납하거나 결제 수단을 등록하지 않는다. 사용자가 입력한 요금표로 계산한 `예상 요금`은 주차장 정산 시스템의 청구 금액이 아니다.
- 주차장 운영사와 공식 계약/API/결제 승인 절차가 확보되면 해당 주차장에 한정해 결제 연동을 별도 검토한다. 일반 주차장 어디서나 쓸 수 있는 범용 결제 API가 있다고 가정하지 않는다.
- 앱인토스 `토스페이` 연동 가능성은 개발자센터의 최신 토스페이 가이드와 콘솔의 파트너/가맹점 조건을 확인한 뒤 판단한다. 사용자 입력한 예상 요금만으로 결제 주문을 생성하지 않는다.
- 앱인토스 인앱 결제(IAP)는 공식 가이드에서 디지털 상품·기능 권한·콘텐츠 판매를 대상으로 안내한다. 오프라인 주차장 이용료 결제에 IAP를 사용하지 않는다.
- 주차장 운영사 연동 전에는 `결제하기`, `자동 정산`, `출차 완료`와 같은 실제 결제/정산을 암시하는 버튼을 만들지 않는다.
- 금융계좌, 카드번호, 토스 잔액, 거래 내역 등 금융정보는 MVP에서 조회·저장하지 않는다.

### 저작권·라이선스

- 경쟁 주차 앱의 디자인·문구·아이콘을 복제하지 않는다.
- 타사 지도 타일·로고·장소 사진을 무단 사용하지 않는다.
- TDS 및 SDK의 현재 라이선스와 이용 조건을 기록한다.
- npm 의존성은 SPDX/라이선스 파일/버전을 감사한다.
- GPL/AGPL/LGPL 등 의무 검토가 필요한 라이선스가 들어오면 추가 전 중단하고 영향 분석을 보고한다.
- 폰트·아이콘·이미지 에셋을 추가할 때 상업적 이용·수정·재배포 조건을 확인한다.
- 이미지 에셋이 전혀 필요하지 않은 UI를 우선한다.
- `docs/LICENSES.md`와 `THIRD_PARTY_NOTICES.md`를 유지한다.

## 13. 개발 단계와 진행 Gate

### Phase 0 — 앱인토스 환경·SDK 검증

1. 현재 디렉터리, Git 상태, Node/npm, 기존 저장소 파일을 조사한다.
2. 기존 Moment Log 프롬프트와 이 주차 전용 요구사항의 범위를 비교해 주차 외 기능을 제외한다.
3. 최신 앱인토스 공식 시작 가이드와 SDK 릴리즈 노트를 확인한다.
4. 공식 CLI로 프로젝트를 생성하거나 기존 프로젝트를 점검한다.
5. SDK 버전, `apps-in-toss.config.ts`, Vite 설정, 빌드 스크립트, 네비게이션 설정을 기록한다.
6. iOS/Android 샌드박스에서 `Device.getLocation` one-shot POC를 수행한다.
7. 위치 권한 거부 후 수동 저장 경로를 확인한다.
8. 토스 `Storage`에 JSON 저장 → 앱 종료 → 재진입 후 복원 POC를 수행한다.
9. 카메라 및 사진 저장 POC는 선택 기능으로 수행한다. 실패해도 전체 MVP 진행은 가능해야 한다.
10. `Device.openURL` 지도 링크 정책·동작을 확인한다. 토스 정책 확인 전 운영 기본값은 false로 둔다.
11. `docs/DECISIONS.md`, `ARCHITECTURE.md`, `TOSS_SDK_COMPATIBILITY.md`, `TOSS_POLICY_CHECKLIST.md`, `COSTS.md`, `LICENSES.md` 작성.

**Phase 0 Gate:** iOS와 Android 토스 앱에서 위치 권한 처리, 로컬 Storage 저장/재진입 복원이 확인되어야 주차 기록 UI를 최종 고정한다. 위치 POC가 실패해도 수동 주차 기록은 계속 개발하되, 미지원 상태를 분명히 한다.

### Phase 1 — 초간단 주차 MVP

- 빈 상태 홈
- 주차 기록 입력 화면
- one-shot 위치 조회
- 주차장명·층·구역·기둥 번호·메모
- 주차 시작 시각 저장 및 경과 시간 타이머
- Storage 저장·복원
- 활성 기록 상세 화면
- 수정·주차 완료·새 기록
- 최근 기록 최대 5개
- 타이머는 앱 종료 후 재진입 시에도 시작 시각 기준으로 정상 갱신

**완료 기준:** 로그인 없이 주차 기록을 만들고, 토스 앱을 종료 후 다시 열어도 현재 주차 정보가 유지된다.

### Phase 2 — 예상 요금 계산 + 사진/지도(선택)

- 단순 요금 규칙 입력 UI: 무료 시간, 기본 요금, 기본 적용 시간, 추가 과금 단위/금액, 1회 주차 상한
- 순수 TypeScript `fee-estimator`와 경계값 테스트
- 활성 주차 화면의 예상 요금 카드 및 실제 정산액 수동 입력(선택)
- 요금표 로컬 저장·선택·수정, 주차 기록별 rateSnapshot 보존
- 일 최대요금/심야·주말/할인/복합 요금 규칙은 자동 계산하지 않음
- 사진 저장 POC 통과 시 1장 사진 첨부
- 이미지 크기 제한·삭제·재진입 복원
- 지도 링크 정책 확인 통과 시 iOS/Android 지도 열기
- 외부 이동 실패/미승인 시 좌표 복사

**완료 기준:** 사진/지도 기능이 실패해도 주차 기록·조회는 정상 동작한다.

### Phase 3 — 선택형 기능성 푸시 알림 POC

- 타이머 자체는 서버 없이 동작하는 것을 유지한다.
- 앱인토스 `Notification.requestAgreement`가 실제로 어떤 동의 UI/상태를 제공하는지 iOS·Android 샌드박스에서 확인한다.
- `anonKey` 발급·검증 API와 `x-anon-key` 기반 기능성 메시지 발송 흐름을 공식 문서로 확인한다.
- 파트너 서버의 mTLS 인증서 구성과 메시지 템플릿 검수, 예약 발송 작업이 필요하다.
- 무료 운영 환경에서 mTLS outbound와 예약 작업이 지속적으로 가능한지 실제 POC 및 한도 검증을 한다.
- 푸시 기능은 사용자가 특정 정산/출차 알림 시각을 선택한 경우에만 제공하고, 동의 철회·알림 취소·주차 종료 시 예약 취소를 지원한다.
- 서버 비용/보안/정책이 무료 우선 기준을 충족하지 못하면 푸시 기능을 보류하고 앱 내 타이머만 제공한다.

**완료 기준:** 푸시를 구현하지 않더라도 MVP가 완결된다. 푸시를 추가할 경우 실제 토스 앱에서 동의·발송·취소까지 검증하고 비용·서버 의존성을 문서화한다.

### Phase 4 — 토스 앱 UI/정책·출시 QA

- 기본 상단 내비게이션·Safe Area 확인
- 위치 권한 사전 안내·거부 대안 확인
- iOS/Android 토스 앱 E2E 테스트
- TDS·아이콘·폰트·SDK 라이선스 감사
- 개인정보·위치정보 고지와 앱 설명 작성
- 앱인토스 콘솔 등록 정보와 실제 `appName` 일치 확인
- 앱인토스 검수 체크리스트 확인
- `README.md` Work Log 및 출시 체크리스트 갱신

### 2026-11-08 기준 외부 검증에서 반드시 반영할 사항

1. 앱인토스 공개 Client SDK 문서 인덱스에는 `Notification.requestAgreement`가 있으나, OS 로컬 알림을 임의의 미래 시각에 예약하는 `scheduleLocalNotification` 형태의 API는 확인되지 않았다. 따라서 로컬 알림을 전제로 하지 않는다.
2. 앱인토스 기능성 메시지는 파트너 서버에서 발송하는 구조이며 서버 인증에 mTLS가 필요하다. 발송 대상은 토스 로그인 `userKey` 또는 로그인 없이 발급받는 `anonKey` 중 하나로 식별할 수 있다.
3. 사용자가 특정 주차 세션의 종료/정산 알림을 요청하는 경우 알림 동의문과 승인된 기능성 메시지 템플릿이 필요할 수 있다. 콘솔에서 모든 사용자에게 보내는 일괄/정기 메시지는 개인별 `reminderAt`을 기준으로 발송하는 기능을 대체하지 못한다. 개인별 알림은 anonKey 기반 서버 발송과 예약 작업이 검증되어야 한다. 콘솔 문구 검수와 실제 알림 수신 동의를 완료하지 않은 발송 코드를 운영에 넣지 않는다.
4. 2026-08-28 앱인토스 공지에 따라 스마트 발송의 광고성 푸시/알림 운영은 2026-10-01 종료됐다. 기능성 푸시·알림 및 알림동의문은 유지된다고 공지됐다. 광고 캠페인 방식으로 개인별 주차 정산 알림을 구현하지 않는다.
5. 앱인토스 인앱 결제 공식 가이드는 디지털 상품·기능 권한·콘텐츠 판매를 대상으로 설명한다. 실제 주차장 이용료 결제 수단으로 IAP를 사용하지 않는다.
6. `토스페이`와 주차장 결제 연동은 별개다. 주차장 운영사의 공식 결제 API/가맹점 관계/정산 흐름이 확인되지 않으면 결제 기능을 개발하지 않는다.
7. 공개 SDK/API 문서·요금·정책은 변경될 수 있으므로 Phase 0에서 링크와 확인일을 기록하고 다시 확인한다.

## 마지막 지시

**주차 위치·경과 시간·사용자 입력 요금표 기반 예상 금액을 기록하고 다시 확인하는 데 필요한 기능만 구현하라.**

첫 번째 완성 목표는 `주차 시작 → 위치 가져오기(선택) → 층/구역/기둥 입력 → 저장 → 타이머 시작 → 다시 진입해 경과 시간 확인`이다. 다음 목표는 `요금표 수동 등록 → 예상 요금 계산 → 차량 찾기 → 실제 정산액 수동 기록`이다.

앱인토스의 네이티브 위치·로컬 Storage를 최대한 활용한다. 기본 타이머·요금 계산은 서버·로그인·유료 API 없이 동작해야 한다. 앱 밖 푸시 알림은 기능성 메시지 공식 연동과 무료 서버 운영 가능성이 확인된 경우에만 선택적으로 추가한다. 실제 주차요금 결제는 주차장 운영사 제휴·API·결제 권한이 확보되기 전까지 구현하지 않는다.

GPS는 주차장 주변 위치를 기록하는 보조 수단이다. 지하 주차장 내부의 정확한 주차면은 사용자가 입력한 층·구역·기둥 번호와 사진(사진 POC 통과 시)으로 보완한다. 타이머는 시작 시각과 현재 시각으로 계산하므로 앱 종료 중에도 시간이 이어지며, 백그라운드 실행을 가장하지 않는다.

**좋은 결과의 기준은 기능이 많은 앱이 아니라, 토스에 들어온 사용자가 주차 위치를 빠르게 남기고, 주차 경과 시간과 예상 요금을 이해한 뒤, 차를 찾을 때 다시 쉽게 확인할 수 있는 가장 단순한 앱이다.**
